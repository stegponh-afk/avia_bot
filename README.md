# Бот: скидки на авиабилеты

Следит за ценами круглосуточно и пишет, когда билет стоит **намного дешевле
обычного** для своего маршрута — как «суперскидки» на Aviasales:

    🔥 Суперскидка 68%
    Казань → Минск · Беларусь
    3 495 ₽  ~~10 986 ₽~~
    26 сен, сб, 21:50 · Pobeda
    на другие даты в сентябре билет стоит от 10 986 ₽ — смотрел 10 дат вылета

Сделан для обычных людей: внизу три кнопки, при первом запуске один вопрос —
«откуда летаешь». Всё остальное бот решает сам.

## Запуск в Docker

Это основной способ. На сервере с прямым доступом к Telegram прокси не нужен —
оставь его пустым.

```bash
cp .env.example .env
```

В `.env` заполнить два поля: `AVIA_BOT_TOKEN` (от @BotFather) и `TP_TOKEN`
(бесплатный, travelpayouts.com → Инструменты → API). Дальше:

```bash
docker compose up -d --build
```

Посмотреть, что живой:

```bash
docker compose logs -f
```

В логах первым делом печатается, с какими настройками поднялся бот, потом
результаты опросов. Обновить после правки кода — `docker compose up -d --build`.

Всё состояние (база цен, справочник, сессия Telegram) лежит в томе `avia-data`
и переживает пересборку. Забрать базу себе:

```bash
docker compose cp bot:/data/avia.db ./avia.db
```

### Чтение каналов про горящие билеты, необязательно

Нужны `TG_API_ID` и `TG_API_HASH` с my.telegram.org, список каналов
в `AVIA_TG_CHANNELS` и `AVIA_TG_WATCH=1`. Telegram при первом входе спрашивает
код, а у контейнера нет терминала — поэтому один раз вручную:

```bash
docker compose run --rm bot python login.py
```

Код придёт **в Telegram**, не в SMS. Скрипт заодно проверит, что все каналы
из списка открываются. После этого `docker compose up -d`.

### Если запускаешь не на сервере, а дома за VPN

`127.0.0.1` внутри контейнера — это сам контейнер, а не твой v2rayN. Поэтому
в `.env` пиши `socks5://host.docker.internal:10808` и раскомментируй
`extra_hosts` в `docker-compose.yml`.

## Запуск без Docker

```bash
pip install -r requirements.txt
python check.py     # покажет, что не поднялось
python run.py
```

Настройки тогда берутся из `config.py`, переменные окружения не нужны.

## Как пользоваться

Первый `/start` задаёт один вопрос — откуда летаешь. Дальше бот сам присылает
скидки от 25%, и в меню четыре кнопки:

| Кнопка | Что там |
|---|---|
| 🔥 Скидки | что сейчас дешевле обычного, большие скидки первыми. Вкладка «💰 Дешевле всего» — просто самые дешёвые билеты за сутки |
| 🔍 Найти билет | цены на свои даты. Можно не нажимать, а сразу написать: `Сочи`, `Сочи 18.10`, `Сочи 18.10 25.10`, `Киров Питер 18.10` |
| 🔔 Мои направления | слежка за конкретным маршрутом, например Киров → Москва |
| ⚙️ Настройки | откуда, что присылать, бюджет, когда лететь |

Всё остальное появляется по ходу дела. Под скидкой — «Купить» и «Все даты».
В календаре направления даты сразу кнопками-ссылками: нажал «14 окт · 4 300 ₽»
и уже на сайте. Там же «Туда и обратно» и «Поискать дешевле с пересадкой».

Кнопки прошлых версий меню у людей остаются на экране, пока бот не пришлёт
новую клавиатуру. Бот их понимает: выполняет и заодно выдаёт новое меню.

### Бот в любом чате (инлайн)

В переписке с кем угодно: `@AviaChecker_bot Сочи` — Telegram покажет самые
дешёвые даты из своего города, нажал — в чат уходит карточка с ценой, кнопкой
«Купить» и ссылкой на бота (`handlers/inline.py`). `Киров Москва` — из другого
города, пустой запрос — лучшие скидки из своей ленты. Ответы по направлению
держатся в памяти 20 минут: Telegram спрашивает на каждую букву. Метки:
`bot_inline` у покупок, `?start=inline` у переходов в бота (видно в «🔗 Ссылки»).
**Включается у @BotFather:** `/setinline` → бот → подсказка «Город, например: Сочи».

В чат уходит карточка, как в канале: картинка (маршрут, цена, погода), под ней
подпись с погодой и кнопки. Картинку в ответ инлайн-режима Telegram принимает
только ссылкой, поэтому бот держит маленький веб-сервер (`cardweb.py`): ответ
кладёт находку в память на час и отдаёт Telegram адрес `/c/<метка>.jpg`,
картинка рисуется, когда Telegram за ней пришёл. Адрес снаружи —
`AVIA_WEB_URL` (`http://IP:8090`), порт — `AVIA_WEB_PORT`, в docker-compose
проброшен 8090. Адрес не задан или порт не поднялся — карточка уходит текстом.

### Итоги месяца

Первого числа после 12:00 — каждому, кому за прошлый месяц пришло хотя бы три
находки: картинка с лучшими скидками и текст — сколько прислал, самая большая
скидка, сколько по своим направлениям и на сколько всё вместе дешевле обычных
цен (`notify.recap_due`). Считается по журналу `sent_log`, куда пишется каждое
уведомление, утренняя сводка и письмо по направлению. Посмотреть свои итоги
за текущий месяц — «📊 Мои итоги месяца» в /admin.

### Ночью бот не пишет

С 23 до 8 (`AVIA_BOT_QUIET`, время сервера) уведомления не уходят. Находки
откладываются (по направлению — одна, свежая) и утром, после первого опроса,
приходят одним сообщением «☀️ Пока ты спал»: до `AVIA_NIGHT_KEEP` (5) лучших —
картинкой в стиле подборок канала (`notify.morning_post`), под ней тот же
список текстом и кнопки, в оформлении, выбранном человеком. Кнопка откроет карточку по свежей ленте, а если скидка
за ночь ушла — календарь направления. Одна находка — сразу карточкой.
Свои направления ночью не проверяются вовсе: утренняя проверка возьмёт
свежие цены и напишет, если есть что.

### Мои направления

Общая рассылка отвечает на «куда улететь подешевле», а людям часто нужен один
маршрут — к родителям, домой, на работу. За ним бот следит отдельно (`watch.py`).

**Как добавить:** кнопка «🔔 Следить за скидками здесь» под календарём
направления; «➕ Добавить» в списке; или просто написать два города —
`Киров Москва` откроет календарь этого маршрута с той же кнопкой. Город
вылета может быть любым, не только из настроек. До `AVIA_WATCH_MAX` (10)
направлений на человека.

**Когда пишет.** Каждый опрос — один запрос на направление: самая дешёвая
цена на каждую дату на год вперёд, в окне дат из настроек человека. Пишет, если
* лучшая цена стала на `AVIA_WATCH_DROP` (10%) дешевле той, что человек уже
  знает: с момента подписки или из прошлого уведомления;
* или появилась скидка от `AVIA_WATCH_PCT` (20%) к обычной цене маршрута, и
  цена хоть немного ниже известной — такое не чаще раза в `AVIA_WATCH_REPEAT` (7) дней.

Цена ушла вверх на те же 10% — «известная» цена тихо поднимается следом, иначе
падение обратно никто бы не заметил. Уведомление — та же карточка, что и
в канале, с плашкой «ПОДЕШЕВЕЛО» (или «СКИДКА», если она к обычной цене
больше) и кнопкой «🔕 Больше не следить».

Цены из проверки пишутся в историю маршрута. У «Киров → Москва» нет общего
обхода, и обычную цену бот узнаёт как раз отсюда: первые дни скидку считает
по соседним датам, потом — по истории.

**Своя цена** — кнопка «🎯» в списке направлений (или «🎯 Указать свою цену»
сразу после добавления): человек пишет сумму, и вместо правил выше бот пишет,
когда билет станет не дороже неё — плашка «ТВОЯ ЦЕНА». Один раз, пока цена
не уйдёт выше и не вернётся; дальше — если подешевело ещё на 10%. `0` — убрать.
Если уже сейчас не дороже — это говорится сразу, отдельным письмом не дублируется.

**Одна дата** — кнопка «🔔 Следить за этой датой» под карточкой билета и
«🔔 Следить за ценой на 18 окт» под ответом на даты (`Киров Москва 18.10`).
Следит только за этим днём вылета, окно дат из настроек не важно; своя цена
работает и тут. Рейс улетел — слежка удаляется сама. В списке —
«Киров → Москва, 18 окт». В базе это `watches.on_date` ('' — любая дата).

### Настройки

* **🛫 Откуда** — город вылета. Проверка двойная: код есть в справочнике
  и из него реально летают. В справочнике 10 тысяч кодов, включая аэропорты
  без рейсов: Белгород там есть, направлений ноль. Новый город бот сразу
  опрашивает в фоне, чтобы лента не пустовала до следующего прохода.
* **🔔 Что присылать** — пять независимых галочек (`subs.alerts`): присылается
  только отмеченное. Можно одну — например, только «Мои направления», —
  несколько или все:
  * 🔥 суперскидки (от 50%) или 💸 все скидки (от 25%) — отметил одно,
    второе снимается: «все» уже включают «супер»;
  * ✈️ дешевле бюджета — любой билет в пределах бюджета, даже без скидки;
  * 🔔 мои направления — уведомления по отслеживаемым маршрутам; выключено —
    маршруты остаются в списке и цены в нём обновляются, но бот молчит;
  * 🏖 куда на выходные — по четвергам в то же время, что и в канале,
    подборка поездок на выходные из своего города (`notify.weekend_due`,
    одна подборка на город вылета, меньше двух вариантов — не шлём).

  У кого выбор был сделан до галочек, он переносится сам: суперскидки →
  🔥 + 🔔, все скидки → 💸 + 🔔, дешевле бюджета → ✈️ + 🔔, ничего → пусто.
  Новым — все скидки и мои направления.
* **💰 Бюджет** — потолок цены. Дороже не присылается, даже со скидкой.
* **📅 Когда** — любые даты, месяц или свой период (`01.12 15.12`).
* **🎨 Оформление** — новое (заголовки и кнопки внутри сообщения) или
  обычное (текст, кнопки под ним) — для тех, у кого новый вид не показывается.

### Служебное: /admin и кнопка «🛠 Админка»

У владельцев (`AVIA_OWNER_IDS`) в нижнем меню пятая кнопка «🛠 Админка» —
то же, что `/admin`. У остальных её нет, а нажатие чужим ничего не делает.

**Ссылки отслеживания** (`links.py`). В админке «➕ Создать ссылку
отслеживания» — бот спрашивает название («youtube», «сторис 1 октября»)
и выдаёт ссылку `t.me/AviaChecker_bot?start=youtube`. Метка делается из
названия латиницей; занята — добавляется номер. В «🔗 Ссылки» — кнопка на
каждую, с числом переходов за сегодня. В карточке ссылки — график по дням
за 30 дней и три строки за сегодня, неделю и месяц:

* **переходы** — сколько раз бота открыли по ссылке (нажали «Запустить»);
  сам клик в YouTube Telegram не сообщает, его не посчитать;
* **новые** — сколько людей пришли в бота впервые;
* **остались** — сколько из новых выбрали город и не заблокировали бота.

Записывается каждый `/start` с меткой, даже если ссылки в списке ещё нет:
создашь ссылку на уже использованную метку — история подтянется. Метка
`channel` (кнопка «Свои уведомления» в постах канала) в списке сразу.


В меню команды нет. Там состояние сборщика, опрос вручную, поиск связок по
всем направлениям и переключатель оформления (обычные сообщения или rich —
с заголовками и кнопками внутри). Кому видна — `AVIA_OWNER_IDS`, пусто = всем,
кто знает команду.

## Как считается скидка

Скидка — это цена против **обычной цены этого маршрута**. Обычную цену бот
узнаёт сам, накапливая наблюдения, и считает её осторожно:

* **по другим датам вылета**, не по той же самой — иначе находка сама тянет
  «обычную цену» вниз и прячет свою скидку;
* **минимум на каждую дату**, а не все тарифы подряд. На одну дату в кэше
  лежат и прямой за 5 000, и три пересадки за 40 000; середина этого —
  не «обычная цена», а случайность;
* **прямой — только с прямыми**. У многих направлений прямой рейс летает по
  определённым дням за 10 000, а в остальные — с пересадками за 40 000.
  Живой пример: Казань → Анталья в апреле. Сравнение без разделения рисовало
  «−69%» на обычном расписании;
* **нижняя четверть**, а не середина. Скидкой называется то, что дешевле даже
  дешёвых дней;
* **с поправкой на сезон**: октябрь сравнивается с октябрём, если дат хватает.

Кроме истории, скидка бывает ещё к трём ориентирам — в сообщении всегда
написано, к какому именно:

* **соседние даты** ±4 дня того же прохода — ловит провал на одном числе;
* **та же дата вчера** — подешевел именно этот рейс, а не «где-то в кэше
  нашёлся день подешевле»;
* **один билет на весь путь** — для связок через третий город.

Кривая «цена от расстояния» процент не называет: на живых данных она объявляла
«−79%» на Сочи за 2 868 ₽, а это обычная цена межсезонья.

История нужна за 3+ разных дня и по 10+ датам вылета, поэтому первые пару суток
на новом городе скидки ловятся только по соседним датам.

### Можно ли поймать скидку в 96%

Если она попадёт в данные — да, и придёт с пометкой «⚡️ цена редкая».
Ограничение не в боте, а в источнике: партнёрский API Aviasales — это **кэш
поисков пользователей**, а не живая выдача. Часть витринных «суперскидок»
приложения туда не попадает. Проверено: билета Казань → Шарм-эш-Шейх за 1 147 ₽
со старого скриншота не было ни в кэше, ни в спецпредложениях ни из одного
из 15 городов. Чтобы поймать больше, бот опрашивает ещё и подборку
спецпредложений Aviasales (`get_special_offers`) — там бывают рейсы, которых
нет в обычном кэше.

## Канал

Бот ведёт канал со скидками из Москвы и Питера и публикует сам. Находки встают
в очередь и выходят по одной — самая большая скидка первой, раз в 10 минут
(`AVIA_CHANNEL_GAP`): 19 постов за минуту заставят подписчиков выключить звук.
С 23 до 8 посты выходят без звука (`AVIA_CHANNEL_QUIET`). Пролежавшее в очереди
дольше 6 часов снимается. Владельцу (`AVIA_OWNER_IDS`) после каждого поста —
строка с кнопками «Открыть» и «🗑 Удалить».

`AVIA_CHANNEL_AUTO=0` возвращает ручной режим: бот присылает готовый пост
с кнопками «✅ Опубликовать / ❌ Пропустить».

**Что попадает:** скидка от 40% к обычной цене маршрута или падение той же даты
за сутки от 25%. Вылет не раньше чем через 2 дня — рейс «сегодня вечером»
никто из читателей не успеет купить. Повтор по направлению — только если
дешевле прошлого черновика на 15% или прошла неделя; пропущенный черновик
считается так же.

**Перед публикацией** цена перепроверяется на ту же дату. Подорожала
больше чем на 3% или билет пропал — пост не уходит, бот пишет почему. Цена
чуть изменилась — карточка перерисовывается с новой.

**После публикации** бот сопровождает пост каждый проход, пока рейс не улетел
(но не дольше недели). Цена изменилась больше чем на 2% — перерисовывает
карточку и пишет «🔄 цена обновлена». Билет пропал или скидка упала ниже 20% —
помечает пост: плашка «НЕ АКТУАЛЬНО» на картинке, «⛔ Уже не актуально»
в подписи, кнопка покупки убирается. Владельцу — строка о каждой правке.
Сверка идёт по кэшу API: живую цену сайта бот видит, когда она туда попадёт.

**Картинка** рисуется самим ботом (`card.py`, Pillow, шрифт Inter), а не
скриншотом сайта: скриншот требует браузера на сервере, ломается от защиты
Aviasales от ботов, и живая цена на нём может не совпасть с постом.

**Погода** (`weather.py`) — строка «☀️ Анталья: днём +26°, ночью +18° —
прогноз на даты поездки» в посте и «днём +26°» на карточке рядом со страной.
Источник — Open-Meteo, бесплатно и без ключа. Прогноз есть на 15 дней вперёд;
дальше — погода в эти же даты год назад, и в тексте честно «обычно в эти
даты». Сервис молчит — пост выходит без погоды. Ответы кэшируются на 3 часа.

**Отели** (`hotels.py`) — кнопка «🏨 Отели: Сочи, 14–19 окт» под постом и
под находкой в боте: поиск отелей в городе прилёта, заезд в день вылета,
выезд в день обратного билета (нет обратного — ссылка на город без дат).
По России — Отелло, если город есть в `otello.json`, остальное — Островок.
Цены на кнопке нет: API цен на отели у Travelpayouts (Hotellook) больше не
отвечает. Список Отелло собран и проверен заранее в браузере: сайт пускает
только через вход Сбер ID, и с сервера адрес не проверить; нового города
в списке нет — уходит в Островок. Адрес города у Островка бот узнаёт сам
(подсказки сайта) и запоминает в базе. Ссылки партнёрские: у каждой
программы своя кампания и erid, их бот спрашивает у Travelpayouts раз в
сутки вместе с Aviasales; метка — `…_hotel`. Программа не подключена
в кабинете — кнопка ведёт на сайт без партнёрки.

**Вид поста** — новый (rich, `AVIA_CHANNEL_RICH=1`): карточка, заголовок,
текст и кнопки внутри поста. Хэштеги в нём размечены, но Telegram пока не
делает их нажимаемыми — поиск по тегу открывается долгим нажатием (в закрепе
теги обычные и нажимаются). Вид запоминается у поста (`posts.fmt`): правка
цены и «не актуально» идут тем же видом, а посты, вышедшие картинкой с
подписью до перехода, правятся по-старому. Новый вид не принят Telegram —
пост уходит картинкой с подписью. `AVIA_CHANNEL_RICH=0` — вернуть старый вид.
Черновики владельцу остаются картинкой: у них кнопки меняются после нажатия.

**В личке бота** находки выглядят так же (`post.py`): та же карточка и
подпись без хэштегов, кнопки «Купить», «Обратно», «Все даты». Билет просто
в бюджете — зелёная плашка «В твоём бюджете» без процента; связка — плашка
«Двумя билетами» с городом пересадки на траектории. В рассылке картинка
рисуется один раз на находку, остальным подписчикам уходит по `file_id`.
Нарисовать не из чего (находка из чужого канала) или Telegram не принял
фото — уходит прежний текстовый экран.

**Подключение.** Бот должен быть админом канала с правом публиковать. Когда
его назначают, он сам запоминает канал и пишет владельцу — id вручную можно
не искать. `AVIA_CHANNEL` в `.env` — запасной вариант.

`/admin` → «📣 Пример черновика» — пост из лучшего, что сейчас есть в ленте,
без порогов: посмотреть, как выглядит, не дожидаясь настоящей скидки.

| Переменная | Смысл |
|---|---|
| `AVIA_CHANNEL` | id канала, если бот не запомнил его сам |
| `AVIA_OWNER_IDS` | кому приходят черновики и кому доступен /admin |
| `AVIA_CHANNEL_ORIGINS` | города вылета, по умолчанию `MOW,LED` |
| `AVIA_CHANNEL_DEAL` / `AVIA_CHANNEL_DROP` | пороги скидки и падения, 40 и 25 |
| `AVIA_CHANNEL_MIN_DAYS` | вылет не раньше чем через столько дней, 2 |
| `AVIA_CHANNEL_REPOST` / `AVIA_CHANNEL_REPOST_DAYS` | правило повторов, 15% и 7 дней |
| `AVIA_CHANNEL_TOL` | на сколько % цена может подрасти к публикации, 3 |
| `AVIA_CHANNEL_SIGN` | подпись в углу карточки |
| `AVIA_CHANNEL_TRACK_DAYS` | сколько дней следить за опубликованным постом, 7 |
| `AVIA_CHANNEL_EDIT_MIN` | мельче скольких % изменение цены пост не трогает, 2 |
| `AVIA_CHANNEL_STALE` | скидка ниже скольких % — «не актуально», 20 |

### Обратный билет и рубрики

В каждом посте — строка «↩️ обратно от 6 200 ₽ — 11 окт, вс · туда-обратно
13 800 ₽» и кнопка покупки обратного билета: самый дешёвый через 2–14 дней
после вылета (`AVIA_CHANNEL_BACK_MIN/MAX`). Один лишний запрос на пост.

Теги сверх города и страны:
* **#наВыходные** — вылет в пятницу или субботу, и есть обратный в воскресенье
  или понедельник не позже чем через три дня. Такой вариант в посте отдельной
  строкой «🏖 на выходные»;
* **#до5000** — билет не дороже 5 000 ₽ (`AVIA_CHANNEL_CHEAP_TAG`).

**Дайджест «Лучшее за неделю»** — по воскресеньям после 12:00
(`AVIA_CHANNEL_DIGEST_DAY/HOUR`): картинка со списком и ссылки на посты.
Меньше трёх постов за неделю — дайджест не выходит.

**«Куда на выходные»** — по четвергам после 18:00
(`AVIA_CHANNEL_WEEKEND_DAY/HOUR`): самые дешёвые поездки туда-обратно на
ближайшие выходные — туда в пт/сб, обратно в вс/пн — из Москвы и Питера, по
пять на город, по сумме двух билетов. «Туда» берётся из свежего обхода (12
самых дешёвых направлений, `AVIA_CHANNEL_WEEKEND_CHECK`), «обратно» — запросом
на каждое. Город в тексте — ссылка на поиск туда-обратно на эти даты (метка
`ch_weekend`). Меньше трёх вариантов — подборка не выходит. Вручную —
«🏖 «Куда на выходные» сейчас» в /admin.

**Сколько постов в день.** Не больше `AVIA_CHANNEL_DAY_MAX` (20) за сутки:
сорок постов в день — это уведомление каждые двадцать минут, от такого
отписываются. Остаток лимита размазывается до 23:00 — пауза между постами
от 10 до 60 минут (`AVIA_CHANNEL_GAP`, `AVIA_CHANNEL_GAP_MAX`), из очереди
всегда берётся самая большая скидка, а то, что пролежало 6 часов, устаревает.
Ночью (23–8) выходят только скидки от `AVIA_CHANNEL_NIGHT_PCT` (50%), без
звука. Подборки и дайджест в лимит не входят.

**Закреп с навигацией** — кнопка «📌 Закреп с навигацией» в /admin. Публикует
пост с тегами и закрепляет; нажать ещё раз — текст обновится на месте.

## Бэкапы и сигналы о поломках

Раз в сутки база копируется штатным механизмом SQLite (снимок без остановки
бота) и сжимается в `/data/backups/avia-ДАТА.db.gz`, хранятся 3 последние
(`AVIA_BACKUP_KEEP`). Мало места на диске — копия не делается, владельцу
приходит сигнал. Восстановить (бот остановлен):

    docker compose stop
    docker run --rm -v avia_avia-data:/data python:3.13-slim sh -c       "gunzip -c /data/backups/avia-2026-09-30.db.gz > /data/avia.db"
    docker compose start

Владельцу (`AVIA_OWNER_IDS`) приходят сигналы: сборщик упал два прохода
подряд, источник цен не вернул ничего ни по одному городу (протух токен,
лимит, сеть), не публикуется в канал, не сделался бэкап. Одна и та же
проблема — не чаще раза в 3 часа (`AVIA_PROBLEM_REPEAT`), когда починилось —
одно сообщение «✅ снова работает».

## Куда ведёт «Купить» и почему бот не проверяет билет на сайте

Кнопки «Купить» (в канале и в боте) ведут на **поиск по маршруту на эту дату**,
а не на конкретный тариф из кэша. Ссылка на тариф (`?t=…`) открывает ровно тот
билет, и если его раскупили, человек видит «Этот билет раскупили». Замер
показал: цены в постах найдены в тот же день, но самые дешёвые места уходят
за часы, а пост живёт днями. Поиск на дату всегда показывает живые цены:
остался тариф — он первый в выдаче, нет — рядом варианты чуть дороже.
Кэшевая ссылка хранится: из неё берутся города пересадок.

Проверить наличие билета «как человек» бот не может, и это решение:
* API живого поиска Travelpayouts выдают проектам от 50 000 MAU, нашему
  ключу он отвечает 403. Его правила к тому же запрещают автоматический сбор
  ссылок из выдачи.
* Браузер на сервере, открывающий партнёрские ссылки, для Travelpayouts
  выглядит как накрутка кликов — за это блокируют партнёрский аккаунт вместе
  с заработком. Плюс защита сайта от роботов и ~400 МБ памяти.

Актуальность после публикации сверяется по кэшу API (сопровождение постов).

## Откуда продажи: метки в ссылках

Все кнопки покупки идут через партнёрские ссылки Travelpayouts
`tp.media/r?…&trs=<проект>&sub_id=<метка>&u=<адрес на aviasales>` — только
такие переходы видны в кабинете как клики. Проекты раздельные: канал —
`TP_TRS_CHANNEL` (579676), бот — `TP_TRS_BOT` (579677). Параметры ссылки,
включая erid (токен маркировки рекламы), бот раз в сутки узнаёт через API
`links/v1/create` и хранит в базе; если API не ответит, работает на
сохранённых, а если их нет — на прямых ссылках `aviasales.ru?marker=728672.метка`
(покупки считаются, клики нет).

Пометка о рекламе в постах канала выключена (`AVIA_AD_LABEL` пуст). Включить —
задать в `.env` текст из кабинета Travelpayouts (кнопка «Отказ от
ответственности в рекламе»): он встанет в конец каждого поста вместе с erid
из параметров партнёрской ссылки (`AVIA_AD_LABEL_ERID=0` — без erid).
Сообщения бота пометку не получают.

Метка источника (SubID) показывает, что продаёт:

| Метка | Откуда переход |
|---|---|
| `ch_<номер поста>` | пост в канале, «Купить» |
| `ch_<номер поста>_back` | пост в канале, «Обратно» |
| `bot_alert` | уведомление бота о скидке |
| `bot_feed` | карточка из ленты «Скидки» |
| `bot_cheap` | список «Дешевле всего» |
| `bot_calendar` | календарь направления |
| `bot_trip` | маршрут на даты |
| `bot_watch` | уведомление по своему направлению |
| `bot_combo` | связка с пересадкой |

Номер поста — id в таблице `posts`; по нему в базе видно маршрут и цену.
Travelpayouts засчитывает покупку в течение 30 дней после перехода, поэтому
метка поста означает «пришёл отсюда», а не «купил именно этот билет».

## Обход направлений и лимиты API

Обычные запросы отдают по городу фиксированный кусок выдачи: одну самую дешёвую
цену на день и около 30 популярных направлений. Скидку на Бодрум из Москвы так
не увидеть. Поэтому раз в 90 минут бот проходит круг по **всем** направлениям
каждого города вылета: прямые маршруты из справочника Travelpayouts плюс всё,
что встречалось в истории. На направление — один запрос, календарь на год
(`grouped_prices` по датам).

Замеры на живых данных: 595 направлений за 7 минут, скидок нашлось 96 вместо
~9, в канал годится 24 вместо 5.

**Лимит API — 600 запросов в минуту** (заголовок `X-Rate-Limit`). Обход идёт
с паузой 0,4 с, это ~150 в минуту. Бот читает остаток лимита из каждого ответа
и, когда остаётся меньше 50, ждёт обнуления окна. Если лимит всё же исчерпан
(ответ 429), бот ждёт до минуты и повторяет запрос.

**Сбой API — не «билетов нет».** Перепроверка цены для канала и маршрут на даты
при сбое сообщают «источник не отвечает», а не «билет пропал». Иначе
сопровождение пометило бы пост «не актуально», хотя билет на месте.

**База.** Обход приносит ~60 тысяч цен за круг, но пишется не больше одной
записи в день на дату вылета и без ссылки — первый круг дня ~60 тысяч строк,
остальные почти ничего. История хранится 100 дней.

| Переменная | Смысл |
|---|---|
| `AVIA_SWEEP` | `0` = без обхода |
| `AVIA_SWEEP_EVERY` | как часто проходить круг, минуты, 90 |
| `AVIA_SWEEP_DELAY` | пауза между запросами обхода, секунды, 0.4 |
| `AVIA_API_RESERVE` | сколько запросов лимита держать в запасе, 50 |

### Связки: что надо понимать

Это **два независимых билета**, купленных отдельно. Опоздал на второй из-за
задержки первого — менять его никто не обязан, деньги не вернут. Багаж надо
получить и сдать заново. Поэтому запас времени на пересадку тут больше обычного:
4 часа в одном аэропорту и 7 часов, если аэропорт другой или неизвестен —
Москва это и Шереметьево, и Домодедово, между ними три часа с чемоданами.
Пересадка дольше 12 часов помечается как ночёвка: гостиница может съесть
всю экономию.

Поиск точечный: бот берёт короткий список направлений и запрашивает календари
по конкретным парам. Широкий скан для этого не годится — проверено на живых
данных: он отдаёт разрозненные даты и круговые тарифы, из-за чего «находки»
оказываются смесью одностороннего билета с билетом туда-обратно.
Календарь по паре, наоборот, даёт полную сетку на месяц, всё в одну сторону
и с временем вылета.

Направления для автопоиска выбираются не случайно: берутся переоценённые
относительно своего расстояния — там, где один билет дорогой, и есть смысл
искать обход. Поиск идёт раз в `AVIA_COMBO_EVERY` минут (по умолчанию 3 часа),
потому что это около минуты запросов на город.

Проверить конкретный город — кнопка «🔀 Поискать дешевле с пересадкой»
под ценами направления или под маршрутом на даты. Такой поиск быстрее (меньше
десятка запросов), поэтому перебирается вдвое больше хабов: `AVIA_COMBO_HUBS_PICK`.
Учитывается и окно дат: если выбран декабрь, связка ищется в декабре.

Если связки в названный город нет, бот не молчит, а показывает самое дешёвое
одним билетом — иначе непонятно, дорого это или нормально.

Связок мало: обычно одна-три. Это нормально, случай редкий. Чтобы находок
было больше, подними `AVIA_COMBO_DESTS` и `AVIA_COMBO_HUBS_N`, опусти
`AVIA_COMBO_SAVE_PCT` — ценой лишних запросов к API.

## Важное про цены

Travelpayouts отдаёт кэш реальных поисков пользователей: данные отстают,
цена **индикативная**. Для «поймать дешёвый билет» этого достаточно, но
финальную стоимость показывает только сайт по ссылке. Расхождение в пару сотен
рублей — норма, в два раза — предложение уже разобрали.

Про `airlines.py` отдельно: сайты почти всех перевозчиков — SPA, цены рисует
JavaScript, и в HTML их попросту нет (S7 отдаёт килобайтную пустую оболочку,
Азимут закрывается от запросов). Поэтому источник выключен. Свою ссылку
проверяй командой `python airlines.py https://...` — если сумм 0 или страница
меньше 5 КБ, добавлять её бессмысленно. Рабочая замена — официальные каналы
перевозчиков в Telegram, они в `AVIA_TG_CHANNELS`.

## Если сломалось

| Симптом | Причина и что делать |
|---|---|
| `Не задан токен бота` | пустой `AVIA_BOT_TOKEN` в `.env` |
| В /admin «Travelpayouts — нет токена» | пустой `TP_TOKEN`, цен взять неоткуда |
| Контейнер `unhealthy` | опрос встал больше чем на три периода, смотри `docker compose logs` |
| Бот не отвечает на сервере | проверь, что сервер вообще ходит в `api.telegram.org` |
| Дома бот не отвечает | не поднят v2rayN, либо в `.env` не `host.docker.internal` |
| Приходит слишком много | в ⚙️ выбрать «только суперскидки» или задать бюджет; поднять `AVIA_DEAL_PCT` |
| Приходит слишком мало | первые 2–3 дня на новом городе это нормально: копится история. Дальше — снизить `AVIA_DEAL_PCT`, увеличить `AVIA_MONTHS` |
| Нет аномалий первые дни | нормально: нужна история, порог 25 наблюдений на направление |
| Даты разъезжаются на день | смени `TZ` в `Dockerfile`, там `Europe/Moscow` |
